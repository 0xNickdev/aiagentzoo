# 智能体如何思考和学习

动物园大部分靠代码运转：哨兵扫描，采集者抓数据，预算和权限由运行时强制执行。模型只在需要判断的地方出场，而判断每天都要和现实对账。

## 循环

```
 夜里       beaver（建造者）── 判断新代币 ──▶ 判断：结论 · 置信度 · 理由
            （每 30 分钟一次，按当前的打法手册）
 黎明       tortoise（档案员）发布带着这些判断的早报
 下一个夜里 beaver ── followup.check ──▶ hedgehog ── 重新读取 DexScreener ──▶ beaver
            beaver 给昨天的判断打分 ──▶ 成绩单（命中、失误、准确率）
            beaver 根据成绩单重写打法手册 ──▶ 打法手册 vN+1
            之后的判断都按 vN+1 来做
```

1. **决定。** 海狸挑出最多 15 个还没判断过的代币，最能说明问题的排在前面（规则标记、毕业、成交量），让模型对每个给出结论：`promising` 看好（明天还活着并有真实流动性）、`suspicious` 可疑（明天之前归零或跑路）或 `watch` 观望（证据不够），附带置信度和一句理由。它依据的打法手册是指令的一部分；代币数据放在不可信数据的围栏里。
2. **核对。** 下一个夜里第一次醒来时，海狸把昨天被判 `promising` 和 `suspicious` 的代币（它自己的和访客的）发给 Northern Edge 上的刺猬。刺猬重新读行情，作为 `followup` 观察发回来。
3. **打分。** 价格跌了 80% 以上或流动性低于 $100 的代币算**死**，流动性 $1,000 以上算**活**，其余未知。还在 pump.fun 内盘上的代币没有池子流动性，所以看内盘市值：低于 32 SOL（回到开盘时的 28 SOL 附近）算**死**，85 SOL 或以上算**活**。DexScreener 从没收录的代币，用动物园自己读取的链上数据按同样的方式判断（[grading.md](grading.md)）。`suspicious` → 死 算命中，`promising` → 活 算命中；`watch` 和未知结果不评分。
4. **学习。** 模型拿到当前的打法手册和打过分的案例，重写打法手册：保留命中的，修改失误的，最多 8 条规则。新版本被存下来，之后的判断就用它。

## 记录在案

| 日志记录 | 内容 |
|---|---|
| `trace calls.made` | 每个结论，带置信度、理由和背后的打法手册版本 |
| `trace calls.scored` | 哪一晚、命中、失误、准确率、每个访客的成绩 |
| `trace playbook.updated` | 新打法手册的全文、版本号和促成这次修改的准确率 |

任何人都可以回放日志，一晚一晚地看海狸的规则怎么变，旁边就是推动每次改变的准确率。早报里的**兽群的判断**和**兽群学到了什么**讲的是同一个故事。

## 没有模型时

没有密钥就没有思考：海狸退回规则判断（两个或以上规则标记 → `suspicious`，置信度 0.5，`by: "rules"`）。这些判断用同样的方式评分，所以战绩照样累积。只有模型在场时，打法手册才会改变。

## 选择模型

节点接入一个可插拔的模型提供方：把提供方的 API 密钥放进节点的环境变量，智能体就会思考；`ZOO_MODEL` 选择模型，不设置就用提供方的默认模型，低强度。任何模型都能接在 SDK 的 `ModelProvider` 接口后面。

每次调用都按智能体的预算（`modelTokens`）计量：海狸每次醒来 24k，乌龟 12k。一晚大约是 50 次判断调用加一次反思。

## 防护

- 打法手册是模型写的文本，所以在存储或展示前会被清洗（不留标记、不留控制字符，最多 10 行、1,500 个字符）。
- 代币名称、备注和行情数据只在 `<untrusted_data>` 里交给模型。
- 判断解析很严格：只保留海狸确实问过的代币上的已知结论。
- 模型能改变海狸*怎么想*，永远改变不了它*能做什么*：能力写在代码里。
